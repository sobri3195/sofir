Fix Elementor conflict - prevent safe mode activation and ensure widget visibility

PROBLEM:
- SOFIR widgets not showing in Elementor editor
- Elementor safe mode automatically activating
- Landing pages displaying but can't edit SOFIR elements
- No dependency or version validation

ROOT CAUSES:
1. Missing Elementor dependency checks
2. No version compatibility validation
3. Inconsistent widget inheritance (some extend Widget_Base directly)
4. No error handling for widget registration
5. Missing PHP version validation

SOLUTIONS IMPLEMENTED:

1. Dependency & Compatibility System (modules/elementor/manager.php):
   - Added is_elementor_compatible() method
   - Validates elementor/loaded action fired
   - Checks Elementor\Plugin class exists
   - Validates PHP 7.4+ requirement
   - Validates Elementor 3.0.0+ requirement
   - Shows admin notices if requirements not met

2. Error Handling for Widget Registration:
   - Wrapped all widget loading in try-catch blocks
   - Graceful degradation if widget fails to load
   - Detailed error logging when WP_DEBUG enabled
   - Applied to main widgets, WooCommerce, EDD, and North Commerce widgets

3. Consistent Widget Inheritance:
   Fixed widgets extending Widget_Base directly:
   - modules/elementor/widgets/voxel-listings.php
   - modules/elementor/widgets/voxel-search-form.php
   Both now extend Sofir\Elementor\BaseWidget for consistency

BENEFITS:
- Prevents safe mode activation with graceful error handling
- Only loads when Elementor properly initialized
- Failed widgets don't break entire integration
- Clear admin notices for requirement issues
- Better debugging with detailed error logs
- Backward compatible with existing pages
- Production ready and multi-site compatible
